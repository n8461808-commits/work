## 1. Что это за проект

Асинхронный менеджер нескольких Telegram-аккаунтов на **Telethon**. Назначение —
**массово добавлять пользователей (`user_id`) в группу/канал** силами многих
аккаунтов одновременно.

Ключевые свойства:
- **Конкурентность** — все аккаунты работают параллельно через `asyncio.gather`.
- **Прокси-на-сессию** — каждому аккаунту свой уникальный прокси (или без прокси).
- **Распределение целей** — список `user_id` делится поровну (round-robin), без дублей.
- **Защита от банов** — аккуратная обработка `FloodWaitError` и `PeerFloodError`:
  проблемный аккаунт паузится/выводится, остальные продолжают.

## 2. Структура файлов

```
login.py              # ИНТЕРАКТИВНЫЙ логин: создаёт .session файл для аккаунта
main.py               # точка входа: собирает всё и запускает аккаунты конкурентно
config.py             # все настройки и пути (берутся из ENV или значений по умолчанию)
proxy_manager.py      # чтение/парсинг прокси (socks5/socks4/http); пусто -> без прокси
session_manager.py    # поиск .session файлов + биндинг прокси-на-сессию
task_distributor.py   # загрузка targets.txt + round-robin раздача user_id
worker.py             # логика ОДНОГО аккаунта + обработка ошибок + само действие
requirements.txt      # зависимости: telethon, python-socks, PySocks
README.md             # пользовательская инструкция по установке/запуску
STRUCTURE.md          # этот файл — карта и handoff
proxies.example.txt   # пример формата прокси (копировать в proxies.txt)
targets.example.txt   # пример списка целей (копировать в targets.txt)
.gitignore            # прячет секреты: sessions/, proxies.txt, targets.txt
```

### Как устроен поток данных (main.py)
1. `discover_sessions()` — находит все `sessions/*.session`.
2. `load_proxies()` — читает `proxies.txt` (если нет/пусто → работа без прокси).
3. `load_targets()` — читает `targets.txt` (user_id, дубликаты отсеиваются).
4. `bind_proxies()` — привязывает прокси к сессиям (1 прокси = 1 сессия).
5. `split_targets()` — делит цели поровну между активными аккаунтами.
6. `asyncio.gather(run_account(...) for each)` — запуск всех аккаунтов параллельно.
7. `run_account()` (в `worker.py`) — подключается, резолвит `TARGET_GROUP`,
   и для каждого `user_id` вызывает `process_target()` (инвайт в группу),
   ловя ошибки.

### Где «само действие»
`worker.process_target()` — сейчас делает `InviteToChannelRequest` (добавление
пользователя в `TARGET_GROUP`). Если нужно другое действие (рассылка и т.п.) —
менять только тело этой функции; обработка флудов уже подключена.

## 3. Настройки (config.py / переменные окружения)

| Параметр | ENV | Значение по умолчанию | Назначение |
|---|---|---|---|
| API_ID | `TG_API_ID` | — | api_id с my.telegram.org |
| API_HASH | `TG_API_HASH` | — | api_hash с my.telegram.org |
| TARGET_GROUP | `TARGET_GROUP` | — | группа/канал куда добавлять (@username без @, или -100... id) |
| SESSIONS_DIR | `SESSIONS_DIR` | `./sessions` | папка с .session |
| PROXIES_FILE | `PROXIES_FILE` | `./proxies.txt` | файл прокси |
| TARGETS_FILE | `TARGETS_FILE` | `./targets.txt` | файл целей |
| ACTION_DELAY | `ACTION_DELAY` | `2.0` | пауза между действиями одного аккаунта, сек |
| PEER_FLOOD_COOLDOWN | `PEER_FLOOD_COOLDOWN` | `3600` | остужение после PeerFloodError, сек |
| MAX_FLOOD_WAIT | `MAX_FLOOD_WAIT` | `300` | порог FloodWait: дольше — аккаунт завершает цикл |
| LOG_LEVEL | `LOG_LEVEL` | `INFO` | уровень логов |

> На Windows в cmd переменные задаются так: `set TG_API_ID=123456` (без export, без $).
> Они живут только в текущем окне cmd.

## 5. ЧТО ДЕЛАТЬ ДОМА — пошагово (Windows + Cursor)

Пользователь придёт домой на свой ПК. Считаем, что Python ещё не настроен.
Веди его по шагам, по одному за раз, жди ответа.

1. **Python**: проверить `py --version`. Если нет — поставить с python.org
   (галочка «Add to PATH»), открыть НОВОЕ окно терминала.
2. **Забрать проект**: если есть git — `git clone -b claude/telethon-async-multi-account-i887pz <repo-url>`.
   Если нет git — скачать ZIP ветки с GitHub и распаковать.
3. **Зависимости**: в папке проекта `py -m pip install -r requirements.txt`.
4. **API-ключи** (у пользователя они уже есть от его авторега; пусть введёт свои):
   ```cmd
   set TG_API_ID=<его api_id>
   set TG_API_HASH=<его api_hash>
   ```
5. **Перелогинить аккаунт** (сессия с прошлого ПК не переехала):
   ```cmd
   py login.py
   ```
   имя `acctest`, прокси — Enter (пропустить), номер с `+`, код из Telegram.
   → создастся `sessions/acctest.session`.
6. **Группа и цели** для теста:
   - создать/выбрать группу-канал, где этот аккаунт состоит и может добавлять;
   - `set TARGET_GROUP=<username_группы_без_@>`;
   - `copy targets.example.txt targets.txt` и вписать туда 1-2 реальных user_id для теста.
7. **Запуск**: `py main.py` → смотреть отчёт в конце.

> Прокси на этом этапе можно не делать — код работает и без `proxies.txt`.

## 7. Важные предостережения (для ассистента и пользователя)

- Аккаунты должны **уже состоять** в `TARGET_GROUP` с правом добавлять участников.
- Массовый инвайт незнакомых людей быстро ловит `PeerFloodError` — это защита
  Telegram, а не баг. На свежих/непрогретых аккаунтах лимит маленький.
- US-аккаунты лучше использовать через US-прокси; вход с «чужого» гео может
  привести к моментальному бану.
- **Секреты не коммитить**: `sessions/`, `proxies.txt`, `targets.txt`, api_hash —
  всё это в `.gitignore` или вводится локально. Не класть их в репозиторий.
- Пользователь — не разработчик. Объяснять простыми словами, давать готовые
  команды, не вываливать всё сразу.
