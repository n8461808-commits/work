# Telethon Multi-Account Manager

Асинхронный менеджер для управления несколькими Telegram-аккаунтами на базе
[Telethon](https://docs.telethon.dev/). Аккаунты работают **конкурентно**
(`asyncio.gather`), каждый — через **свой уникальный прокси**, а список целей
**делится поровну** между аккаунтами, чтобы задачи не дублировались.

> ⚠️ Используйте инструмент ответственно и в рамках
> [Terms of Service Telegram](https://telegram.org/tos). Массовые действия без
> согласия пользователей могут привести к блокировке аккаунтов.

## Возможности

- **Многоаккаунтная конкурентность** — все сессии запускаются одновременно через `asyncio.gather`.
- **Прокси-на-сессию** — каждому `.session` назначается уникальный прокси (HTTP / SOCKS5 / SOCKS4).
- **Равномерное распределение целей** — round-robin раздача `user_id`, без дублей.
- **Строгая обработка ошибок** — `FloodWaitError` и `PeerFloodError` не роняют процесс: проблемный аккаунт паузится/выводится, остальные продолжают.

## Структура проекта

```
config.py             # все пути и параметры (можно переопределять через ENV)
proxy_manager.py      # чтение и парсинг прокси
session_manager.py    # поиск .session файлов и биндинг прокси-на-сессию
task_distributor.py   # загрузка и распределение списка user_id
worker.py             # логика одного аккаунта + обработка ошибок (точка расширения)
main.py               # точка входа: сборка, распределение, запуск
```

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка

1. **API-ключи.** Получите `api_id` и `api_hash` на https://my.telegram.org и задайте их:
   ```bash
   export TG_API_ID=123456
   export TG_API_HASH=abcdef0123456789abcdef0123456789
   ```
   (или впишите прямо в `config.py`).

2. **Сессии.** Сложите авторизованные `.session` файлы Telethon в папку `sessions/`
   (по одному файлу на аккаунт). Имя файла = имя аккаунта в логах.

3. **Прокси.** Скопируйте пример и заполните своими прокси:
   ```bash
   cp proxies.example.txt proxies.txt
   ```
   Формат строки: `type:host:port` или `type:host:port:user:pass`,
   где `type` ∈ `socks5 | socks4 | http`. Порядок строк определяет привязку:
   1-я строка → 1-я сессия и т.д.

4. **Цели.** Скопируйте пример и заполните списком `user_id`:
   ```bash
   cp targets.example.txt targets.txt
   ```

5. **Целевая группа.** Укажите, куда добавлять пользователей:
   ```bash
   export TARGET_GROUP=mygroup          # @username без @, либо -100123... id
   ```
   ⚠️ Все аккаунты должны **уже состоять** в этой группе и иметь право
   добавлять участников, иначе аккаунт будет пропущен.

### Параметры (config.py / переменные окружения)

| Параметр | ENV | По умолчанию | Назначение |
|---|---|---|---|
| `TARGET_GROUP` | `TARGET_GROUP` | — | Группа/канал, куда добавлять пользователей (@username или id) |
| `ACTION_DELAY` | `ACTION_DELAY` | `2.0` | Пауза между действиями одного аккаунта, сек |
| `PEER_FLOOD_COOLDOWN` | `PEER_FLOOD_COOLDOWN` | `3600` | Остужение аккаунта после `PeerFloodError`, сек |
| `MAX_FLOOD_WAIT` | `MAX_FLOOD_WAIT` | `300` | Порог `FloodWait`: дольше — аккаунт завершает цикл (`0` = ждать всегда) |
| `LOG_LEVEL` | `LOG_LEVEL` | `INFO` | Уровень логирования |
| `SESSIONS_DIR` | `SESSIONS_DIR` | `./sessions` | Папка с `.session` |
| `PROXIES_FILE` | `PROXIES_FILE` | `./proxies.txt` | Файл с прокси |
| `TARGETS_FILE` | `TARGETS_FILE` | `./targets.txt` | Файл с целями |

## Запуск

```bash
python main.py
```

В конце выводится сводный отчёт: сколько целей обработано/пропущено/с ошибками
по каждому аккаунту и причина останова, если была.

## Действие: добавление в группу/канал

Сейчас `worker.process_target()` добавляет каждого `user_id` в `TARGET_GROUP`
через `InviteToChannelRequest`. Целевая группа резолвится один раз на аккаунт.

Разбираются «мягкие» ошибки инвайта (пропуск конкретной цели):
приватность, не во взаимных контактах, уже участник, кикнут, заблокировал,
перебор групп. «Жёсткие» (`PeerFloodError`, нет прав админа, бан аккаунта)
выводят аккаунт из работы, не роняя остальные.

Чтобы поменять действие на другое (рассылка и т.п.) — правьте тело
`process_target()`; обработка флудов уже подключена.

## Безопасность

`proxies.txt`, `targets.txt` и папка `sessions/` добавлены в `.gitignore` —
они содержат секреты и не должны попадать в репозиторий.
